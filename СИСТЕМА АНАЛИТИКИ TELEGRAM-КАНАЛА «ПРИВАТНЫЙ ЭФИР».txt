1. ЧТО ЭТО ЗА СИСТЕМА И ЗАЧЕМ ОНА НУЖНА
--------------------------------------------------------------------------------

Система автоматически собирает статистику Telegram-канала «Приватный эфир»
(t.me/Private_ether) и записывает её в Google-таблицу. Без ручного труда:
каждые 6 часов скрипт сам снимает метрики и обновляет таблицу.

Что собирается:
  - просмотры каждого поста (текущие + срезы через 24 и 72 часа)
  - реакции (всего и по эмодзи)
  - пересылки и комментарии
  - число подписчиков и его динамика (кто пришёл / кто ушёл)

Зачем: принимать решения по контенту на данных, а не на ощущениях.
Дополнительная ценность: система - рабочий пет-проект для портфолио
продакта/аналитика (Python, API, автоматизация, метрики).

2. АРХИТЕКТУРА: КАК ВСЁ УСТРОЕНО
--------------------------------------------------------------------------------

  Telegram-канал
       |
       |  Telethon (доступ от имени владельца, НЕ бот -
       |  боты не видят просмотры постов)
       v
  stats.py (Python-скрипт)
       |
       |  gspread (Google Sheets API, вход через сервисный аккаунт)
       v
  Google-таблица «Приватный эфир - Аналитика»
       ^
       |
  GitHub Actions - запускает stats.py по расписанию каждые 6 часов
  (примерно 05:00, 11:30, 16:00, 22:00 МСК; время может плавать
  на 10-30 минут - это нормально для GitHub)

Ключевая идея: скрипт живёт в облаке (GitHub) и не зависит от того,
включён ли ноутбук. Локальный запуск нужен только для разработки и проверок.

4. ЛИСТЫ GOOGLE-ТАБЛИЦЫ
--------------------------------------------------------------------------------

КАНАЛ      Паспорт канала: название, username, подписчики, описание.
           Перезаписывается каждый запуск.

ПОСТЫ      Главный лист: строка = пост, все метрики. Перезаписывается
           каждый запуск, НО ручные и разовые значения сохраняются
           (см. раздел 5, колонки F, G, J, M).

ДАШБОРД    Витрина: KPI-карточки, топ-5 постов, сводка по неделям.
           Полностью пересобирается каждый запуск.

ДИНАМИКА   История подписчиков: 4 строки в сутки (дата, всего, пришло,
           ушло). Скрипт ТОЛЬКО дописывает строки - история не стирается
           никогда, даже при сбоях. Подробнее - раздел 8.

_АУДИТОРИЯ Служебный скрытый лист: слепок Telegram ID подписчиков для
           сравнения между запусками. Руками не трогать. Подробнее -
           разделы 8 и 9.

--------------------------------------------------------------------------------
5. КОЛОНКИ ЛИСТА «ПОСТЫ»
--------------------------------------------------------------------------------

  A  ID               - номер сообщения в Telegram. Авто.
  B  Дата             - дата публикации, ВСЕГДА в UTC (МСК = UTC+3).
                        От этой даты считаются окна 24ч/72ч. Авто.
  C  Ссылка           - прямая ссылка на пост. Авто.
  D  Превью текста    - первые 80 символов поста. Авто.
  E  Просм. сейчас    - просмотры на момент последнего запуска. Авто,
                        обновляется каждый запуск.
  F  Просм. 24ч       - просмотры через ~24 часа после публикации.
                        АВТО (см. раздел 7). Можно ввести руками -
                        скрипт ручное значение не перезапишет.
  G  Просм. 72ч       - то же для 72 часов. АВТО.
  H  Реакции (всего)  - сумма всех реакций. Авто.
  I  Реакции (детально) - разбивка по эмодзи. Авто.
  J  Подписчики       - число подписчиков, зафиксированное при первом
                        появлении поста в таблице. Дальше не меняется -
                        это «база» для расчёта охвата.
  K  1-Day Reach %    - формула, см. раздел 6.
  L  ER поста %       - формула, см. раздел 6.
  M  Комментарий      - твои заметки. ТОЛЬКО вручную, скрипт сохраняет.
  N  Пересылки        - сколько раз пост переслали. Авто.
  O  Комментарии (шт) - число комментариев под постом. Авто.
  P  ERR %            - формула, см. раздел 6.

Жёлтая заливка ячейки = в неё допустим ручной ввод.
Цвет строки: зелёный = ER > 50, красный = ER < 20, иначе обычная зебра.

--------------------------------------------------------------------------------
6. МЕТРИКИ: ФОРМУЛЫ И СМЫСЛ
--------------------------------------------------------------------------------

1-DAY REACH % (K) = Просм.24ч / Подписчики * 100
  Какая доля базы увидела пост в первые сутки. Главная метрика скорости
  охвата. Пустая, пока нет данных в F (пустота лучше фальшивого нуля -
  ноль занижал бы средние).

ER ПОСТА % (L) = Реакции / Подписчики * 100
  Старая метрика вовлечённости. Оставлена, чтобы новые данные можно было
  сравнивать со старыми записями.

ERR % (P) = (Реакции + Пересылки + Комментарии) / Просмотры * 100
  Более честная вовлечённость: учитывает все действия и делит на тех,
  кто реально видел пост. Основная метрика для сравнения постов между
  собой. Ориентиры для малых каналов: > 10% - отлично, 5-10% - норма.

ВАЖНО ПРО ФОРМУЛЫ: таблица в русской локали, разделитель аргументов
в формулах - точка с запятой ";" (не запятая). Если когда-нибудь будешь
править формулы руками - помни про это, иначе получишь #ERROR!.

--------------------------------------------------------------------------------
7. АВТОЗАПОЛНЕНИЕ 24ч / 72ч - КАК РАБОТАЕТ
--------------------------------------------------------------------------------

Telegram не хранит историю просмотров - только текущее число. Поэтому
срез «просмотры через 24 часа» можно получить одним способом: посмотреть
значение В НУЖНЫЙ МОМЕНТ. Это и делает скрипт.

Логика (при каждом запуске, для каждого поста):
  1. Считает возраст поста в часах (от даты в колонке B, UTC).
  2. Если возраст 24-48 ч И ячейка F пустая -> записывает в F текущие
     просмотры.
  3. Если возраст 72-96 ч И ячейка G пустая -> записывает в G.
  4. Заполненные ячейки НИКОГДА не перезаписываются (в т.ч. ручные).
  5. Если окно упущено (все запуски в окне сорвались) - ячейка честно
     остаётся пустой. Пустота = «нет данных», это лучше выдуманной цифры.

Точность: запуск каждые 6 часов -> значение фиксируется с опозданием
до +6 часов от ровной отметки. Для анализа трендов это приемлемо.
Окно шириной в сутки даёт 3-4 попытки - один сбойный запуск ничего
не ломает.

Посты, опубликованные ДО внедрения автозаполнения (июль 2026), частично
без данных в F/G - их окна прошли до запуска фичи. Это нормально.

--------------------------------------------------------------------------------
8. ЛИСТ «ДИНАМИКА» - ИСТОРИЯ ПОДПИСЧИКОВ
--------------------------------------------------------------------------------

Зачем: общее число подписчиков может стоять на месте, пока внутри идёт
ротация (одни уходят, другие приходят). «Динамика» показывает именно
ротацию - это разница между проблемой удержания и проблемой привлечения:
  - Пришло 3 / Ушло 3 -> контент находят, но он не удерживает (retention)
  - Пришло 0 / Ушло 0 -> канал просто никто не находит (acquisition)
Лечатся эти проблемы по-разному, поэтому различать их критично.

Как работает:
  1. Скрипт получает список Telegram ID всех подписчиков (доступно
     владельцу канала).
  2. Сравнивает со слепком прошлого запуска (лист _Аудитория).
  3. Новые ID = «Пришло», исчезнувшие = «Ушло».
  4. Дописывает строку в «Динамику»: дата (UTC), всего, пришло, ушло.
  5. Сохраняет свежий слепок в _Аудитория и прячет этот лист.

Особенности:
  - Append-only: скрипт только добавляет строки. Историю не стирает
    ничто, даже сбой в других частях скрипта.
  - Самая первая строка - точка отсчёта, «Пришло/Ушло» в ней пустые.
  - Шапка самовосстанавливается: если пропала - скрипт вставит её
    заново, не тронув данные.
  - 4 строки в сутки. Для графика за месяц - около 120 точек.

9. ПРИВАТНОСТЬ И ПРАВИЛА ШАРИНГА
--------------------------------------------------------------------------------

В таблице нет имён и username подписчиков. Единственные чувствительные
данные - числовые Telegram ID на скрытом листе _Аудитория.

ГЛАВНОЕ ПРАВИЛО: делясь таблицей, выдавай ТОЛЬКО роль «Читатель».
  - Читатель не может открыть скрытые листы - _Аудитория для него
    не существует.
  - Редактор МОЖЕТ показать скрытые листы. Роль «Редактор» - никому.

Самому посмотреть скрытый лист: Вид -> Скрытые листы -> _Аудитория.
Скрыть обратно: правый клик по ярлыку листа -> Скрыть лист (или просто
дождись следующего запуска - скрипт скроет сам).

10. ЗАПУСК: ОБЛАКО И ЛОКАЛЬНО
--------------------------------------------------------------------------------

ОБЛАКО (основной режим, ничего делать не нужно):
  GitHub Actions запускает скрипт каждые 6 часов сам. Проверка:

  переменной GOOGLE_CREDENTIALS) и берёт секреты из GitHub.

ЛОКАЛЬНО (для разработки и проверок):
  cd C:\telegran-stats
  python stats.py
  Секреты берутся из .env и json-файла в папке. Сессия Telegram - из
  файла session.session: телефон и код скрипт спросит только при самом
  первом запуске в папке, дальше входит сам.

11. КАК ВНОСИТЬ ИЗМЕНЕНИЯ В КОД
--------------------------------------------------------------------------------

Рабочий цикл (всегда одинаковый):
  1. git pull                       - забрать актуальную версию
  2. правишь stats.py в VS Code
  3. python stats.py                - локальная проверка (4 галочки:
                                      Канал, Посты, Дашборд, Динамика)
  4. проверяешь глазами таблицу
  5. git add stats.py               - ТОЛЬКО нужный файл, НЕ "git add ."
  6. git commit -m "что сделал"
  7. git push
  8. вкладка Actions: дождаться зелёного запуска

ЗАПРЕЩЕНО: git add . (риск залить секреты), правки кода без локальной
проверки, ручное редактирование авто-колонок таблицы (перезапишутся).

12. ТИПОВЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
--------------------------------------------------------------------------------

#ERROR! в колонках формул (K, L, P)
  Причина: формула с запятыми вместо точек с запятой (русская локаль).
  Решение: скрипт пишет формулы правильно - просто дождись следующего
  запуска, он перезапишет. Если правил формулы руками - используй ";".

F и G не заполняются у нового поста
  Проверь: (1) Actions - запуски были в окне 24-48ч от публикации и
  зелёные? (2) дата в колонке B - UTC, окно считается от неё, а не от
  МСК. Если запуски красные - открой лог и смотри ошибку.

Красный запуск в Actions с ошибкой про session/auth
  Протухла SESSION_STRING. Сгенерировать новую: локально запустить
  get_session.py (лежит в старой папке C:\TelegramStats), полученную
  строку вставить в GitHub -> Settings -> Secrets -> SESSION_STRING.

TypeError: the JSON object must be str... NoneType (локально)
  Нет переменной GOOGLE_CREDENTIALS и не найден json-файл ключа.
  Решение: проверь, что telegramstats-500216-...json лежит в папке.

Скрипт локально просит телефон и код
  Нет файла session.session в текущей папке. Введи один раз - создастся.

Запусков в Actions нет уже сутки+
  GitHub отключает расписание после 60 дней без активности в
  репозитории. Решение: любой коммит реанимирует, либо кнопка
  Enable workflow во вкладке Actions.

Динамика: строка без шапки / шапка исчезла
  Скрипт восстановит шапку сам при следующем запуске.

Осознанные компромиссы (знаем и приняли):
  - Точность срезов 24ч/72ч: до +6 часов (шаг расписания). Для трендов
    достаточно, ровные отметки потребовали бы сервер 24/7.
  - Если скрипт упадёт в секундном окне между очисткой и записью слепка
    аудитории - потеряется одна точка «пришло/ушло» из четырёх за день.
    Вероятность мизерная, усложнять код ради неё не стали.
  - «Динамика» копит 120 строк/месяц: через несколько месяцев для
    графиков захочется дневная агрегация. Отложено сознательно.
